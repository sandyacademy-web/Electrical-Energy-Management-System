EEMS Architecture

Data Flow & Integration

Spesifikasi resmi mengenai bagaimana data EEMS dikumpulkan, divalidasi, distandardisasi, diintegrasikan, diproses menjadi indikator, disajikan melalui Dashboard, dan diterbitkan sebagai Management Report.

EEMS DATA FLOW & INTEGRATION — SPECIFICATION v1.0
01 — Purpose

Tujuan Integrasi Data

Menetapkan satu arsitektur aliran data yang konsisten untuk seluruh lingkungan EEMS.

01

Single Information Architecture

Seluruh modul EEMS menggunakan struktur data yang terdefinisi dan dapat ditelusuri.

02

Data Integrity

Data yang masuk ke Data Center harus melewati aturan validasi dan standardisasi sebelum digunakan untuk analisis.

02 — Core Architecture

Arsitektur Aliran Data

DATA SOURCE Input & operational records
VALIDATION Quality & completeness
DATA CENTER Central information layer
KPI ENGINE Calculation & analysis
DASHBOARD Management information
REPORT Management output
03 — Data Layers

Lapisan Data EEMS

Data dibedakan berdasarkan fungsi dan karakteristiknya.

Master Data

Data referensi yang menjadi identitas dasar objek EEMS seperti asset, lokasi, person, organisasi, vendor, dan customer.

Transaction Data

Data kejadian dan aktivitas operasional seperti meter reading, maintenance, inspection, incident, project, dan transaksi lainnya.

Analytical Data

Data hasil pengolahan yang digunakan untuk KPI, trend, exception analysis, Dashboard, dan Management Report.

05 — Data Validation

Validasi Data

Data tidak langsung dianggap valid hanya karena telah berhasil dimasukkan ke sistem.

01

Completeness

Memastikan field wajib telah terisi dan tidak terdapat informasi penting yang hilang.

02

Validity

Memastikan nilai sesuai dengan tipe data, format, rentang, dan aturan bisnis.

03

Consistency

Memastikan hubungan antar-record dan antar-modul tetap konsisten.

06 — Standardization

Standardisasi Data

Data Dictionary sebagai Referensi

Setiap field resmi EEMS harus memiliki nama, definisi, tipe data, satuan, aturan pengisian, dan status penggunaannya.

  • Field Name
  • Business Definition
  • Data Type
  • Unit of Measure
  • Required / Optional
  • Validation Rule

Identitas Data

Setiap record harus mempunyai identitas yang memungkinkan data dilacak kembali ke sumbernya.

  • Record ID
  • Source Module
  • Created Date
  • Created By
  • Updated Date
  • Updated By

Data Center sebagai Integration Layer

Data Center menjadi titik integrasi informasi, bukan sekadar tempat penyimpanan file.

RECEIVE Menerima data
VALIDATE Memeriksa kualitas
STANDARDIZE Menyeragamkan
INTEGRATE Menghubungkan
STORE Menyimpan
PROCESS Mengolah
08 — KPI Layer

KPI & Analytical Layer

KPI harus mempunyai definisi, sumber data, periode, satuan, dan formula yang dapat ditelusuri.

KPI Source Unit Calculation Output

Beban Puncak Electrical / Energy kW Maximum Demand Dashboard
Energy Cost Energy / Finance Rp Energy × Tariff Dashboard
Maintenance Status Maintenance % Completed / Planned Dashboard
Project Progress Project % Actual / Planned Dashboard
09 — Dashboard

Dashboard sebagai Information Layer

Prinsip utama

Dashboard tidak menjadi sumber data utama. Dashboard membaca data terstruktur dan hasil analisis dari Data Center dan KPI Layer.


KPI

Menampilkan indikator utama yang relevan dengan kebutuhan manajemen.

Trend

Menampilkan perubahan data berdasarkan periode waktu yang ditentukan.

Exception

Menunjukkan kondisi yang membutuhkan perhatian atau tindakan manajemen.

10 — Management Report

Output Manajemen

Dashboard → Report

Informasi Dashboard dapat menjadi dasar penyusunan laporan manajemen berdasarkan periode dan kebutuhan organisasi.

Report → Action

Temuan dan indikator yang memerlukan tindakan dapat diteruskan menjadi corrective action, preventive action, project, atau improvement.

11 — Data Lifecycle

Siklus Hidup Data

01. Create Data dibuat oleh sumber yang berwenang.
02. Validate Data diperiksa kualitas dan kelengkapannya.
03. Approve Data tertentu mendapatkan persetujuan sesuai kewenangan.
04. Process Data diolah menjadi informasi dan indikator.
05. Report Informasi disajikan kepada manajemen.
06. Archive Data historis disimpan sesuai kebijakan retensi.
12 — Data Governance

Kepemilikan & Pengendalian Data

Data Owner

Bertanggung jawab terhadap makna bisnis, kualitas, dan penggunaan data dalam domainnya.

Data Custodian

Bertanggung jawab terhadap penyimpanan, keamanan, akses, dan pemeliharaan teknis data.

Data User

Menggunakan data sesuai kewenangan, kebutuhan pekerjaan, dan aturan EEMS.

13 — Audit Trail

Ketertelusuran Data

Traceability

Setiap data penting harus dapat ditelusuri dari output kembali menuju record sumbernya, termasuk perubahan, waktu perubahan, dan pihak yang melakukan perubahan sesuai mekanisme kontrol EEMS.

14 — Integration Rules

Aturan Integrasi

  • Setiap modul menggunakan ID dan field yang mengikuti Data Dictionary resmi EEMS.
  • Data yang belum lolos validasi tidak digunakan sebagai dasar KPI resmi.
  • Dashboard tidak menjadi tempat penyimpanan data transaksi utama.
  • Formula KPI harus dapat ditelusuri ke sumber data dan definisi indikatornya.
  • Perubahan data penting harus dapat dicatat melalui mekanisme audit trail.
  • Data historis tidak dihapus tanpa mengikuti kebijakan retensi dan kontrol yang berlaku.
  • Integrasi antar-modul harus mempertahankan identitas record dan referential integrity.

06

Management Report

EEMS Core Principle

One Data Flow. One Information Architecture.

EEMS dibangun bukan sebagai kumpulan halaman yang berdiri sendiri. Setiap modul menghasilkan data, Data Center mengintegrasikan dan mengendalikan data, KPI Layer mengolahnya menjadi indikator, Dashboard menyajikan informasi, dan Management Report membawa informasi tersebut kembali ke proses pengendalian dan improvement.
